# Two failures on 2026-10-26: bootsnap 1.26 cannot boot actionagent 1.9.4, and a staging deploy lost its Google token

Date: 2026-10-26 · Status: gem fix open (activeagent#639); staging re-run green

Justin: "Looks like some failures on ActiveAgents/activeagents".

## 1. Dependabot #168 (bootsnap 1.22.0 → 1.26.0): CI `boot` and `test` fail

```
vendor/bundle/ruby/3.4.0/gems/actionagent-1.9.4/app/models/action_agent/provider_key.rb:264:
argument stack underflow (-1) (SyntaxError)
```

### Cause

`ProviderKey#owner_record` had

```ruby
owner = owner.__getobj__ while defined?(::Delegator) && owner.is_a?(::Delegator)
```

Prism (Ruby 3.4.x and 4.0.x) compiles that line fine by path
(`RubyVM::InstructionSequence.compile_file`) but miscompiles it when the
same source is compiled **from a string** (`compile` / `compile_prism`).
bootsnap 1.24.6 and later compile files from their contents on those Rubies
as the workaround for Ruby bug #22023, so the engine cannot boot under
bootsnap ≥ 1.24.6. bootsnap 1.22.0 on `main` never takes that path, which is
why `main` is green and only the bump fails.

Reproduced locally with a probe that compiles the file both ways: 3.3.8 ok
both ways; 3.4.9 and 4.0.1 ok by path, "argument stack underflow" from a
string. The same construct is what had been breaking local engine runs on
mise Ruby 3.4.9 and 4.0.1 since 2026-10-19 (the gem's
`local-ruby-version-gotcha` note): not a general compiler bug, this one line.

### Fix

Gem PR [activeagent#639](https://github.com/activeagents/activeagent/pull/639)
(`fix/prism-while-defined`): `if defined?(::Delegator)` wraps the unwrap
loop, and `actionagent/test/prism_string_compile_test.rb` compiles every
shipped Ruby file from a string so the next such construct fails in the
gem's CI instead of at a host's boot. On Ruby 4.0.1 the test fails with
exactly this line on `main` and passes with the fix.

### What to do with #168

Leave it until the gem fix is released and the host pins that version; then
re-run its checks (or let dependabot rebase) and merge. Nothing on `main`
or in production is affected: both run bootsnap 1.22.0.

## 2. Deploy to Staging run 40358457242 (`2c0945b`, the docs merge #226): `build` failed

```
ERROR: (gcloud.auth.docker-helper) There was a problem refreshing your current auth tokens:
('Unable to retrieve Identity Pool subject token', 'upstream request timeout')
ERROR: failed to push us-central1-docker.pkg.dev/active-agents-platform/activeagents/activeagents:2c0945b…
```

Workload identity federation timed out while buildx was pushing the image;
the layers had been built and cached. Transient on Google's side, nothing in
the commit (docs only). `gh run rerun 40358457242 --failed` re-ran `build`,
which passed on the second try; see the log below for the deploy result.
Production was deployed from `395fc94` minutes earlier (run 40357092874) and
is unaffected.
