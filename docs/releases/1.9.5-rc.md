## Staging test plan

Prerequisites on the staging GitHub App (done 2026-10-27): install
callback among the redirect URIs, user authorization during installation,
redirect on update, Organization → Members read, webhook active at
`https://staging.activeagents.ai/dashboard/api/github_app/webhooks` with
the secret stored as `activeagents-staging-github-app-webhook-secret` v2.

1. Deploy: the dispatch runs CI → build → Terraform apply → migrate (adds
   `github_webhook_deliveries`) → smoke test.
2. Settings → Integrations: the linked installation is still listed; the
   repository picker opens; pick one repository.
3. Projects → New project: the checklist's GitHub connection item passes
   with only the App linked; the picker lists the installation's
   repositories; create a project and boot it.
4. Webhooks: in the App's Advanced tab, redeliver a recent delivery; the
   dashboard answers 202 (a 404 means the engine isn't the RC). Remove a
   repository from the installation on GitHub and check the selection
   drops it; suspend and unsuspend and watch the card.
5. Evaluations: open a run, copy its link, open it in a new tab.
6. CLI: `gem build` from the engine checkout is not needed; run
   `bin/activeagent --help` from the engine worktree against staging with a
   dashboard API key, then `evals list` and `catalogs list`.

Fixes found by the boot:

- `db:prepare` failed with `role "user" does not exist`: the boot spec's
  server database URLs (`postgresql:///<db>_sandbox_<id>`) carried no user,
  so the checkout's `database.yml` user (`user`) won. `BootSpec#server_url`
  now names the runtime image's roles: `postgresql://sandbox@localhost/…`,
  `mysql2://root@localhost/…` (46822d8).
- The sign-in modal stayed at "Preparing Claude's authorization page":
  Claude Code 2.1 sends sign-ins to `claude.com/cai/oauth/authorize` and
  prints the link as an OSC 8 terminal hyperlink. The relay's URL match ran
  past the hyperlink's terminator into the repeated link text, and the
  service's allowlist named only `claude.ai` / `platform.claude.com`
  (4ff3c3f, a68006c). The same two bugs sat in the engine's local-sandbox
  login (`claude_login_process.rb`, `local_sandbox_claude_login.rb`): fixed
  on engine PR #651 (50088ad4), so they ship in 1.9.5.
- Engine issue #650 (not a blocker): `boot_status` answers 500 while the
  backend is unreachable or before the container writes `state.json`.

Host-side gotchas worth keeping (also in docs/infrastructure/app-runtime.md):
`/opt/activeagents` on the host needs `git config --global --add
safe.directory /opt/activeagents` before `sudo git fetch`; the image build
leaves `app-runtime-builder-<epoch>` containers behind and sorts before the
sandboxes in `incus list`, so name the sandbox container explicitly; the
built image carries whatever the host checkout holds, so after a relay
change rebuild it (`sudo scripts/build-app-runtime-image.sh`) or push the
file into running containers with `incus file push`.
